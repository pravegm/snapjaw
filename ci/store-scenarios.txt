# Snapjaw App Store frames, iPhone sets (docs/appstore/screenshots.md, section A). This file is the source of truth for
# the frames and captions (screenshots.md quotes it): change a caption here, not only there.
# Run by .github/workflows/store.yml: ci/store-capture.sh phone → ci/screenshots.sh (SCENARIOS=this file,
# SCENARIO_FILTER='^P[0-9]', WAIT_FREEZE=1) on the iPhone 18 Pro Max (6.9", 2868 x 1320) and the iPhone 18 Pro (6.3",
# 2622 x 1206, Apple's one required iPhone size), then ci/store-set.sh captions them (ci/store-frame.swift) into
# <set>/store/ with a MANIFEST. The Duo set lives in ci/duo-store-scenarios.txt. Names are zero-padded (P01–P10) so the
# upload folder sorts in frame order, and they are exactly the names tools/appstore/build-metadata.js lists (PFRAMES).
#
# name|demo args (Snap/App/DemoMode.swift)|seconds to wait|caption: headline / sub-line|expect (extra log regex)|frame
#  - wait: a freezeOn=<tag> scenario waits for the app's "SNAP-T freeze <tag>" line instead (at least this long, at
#    least 60 s), then 2 s. freezeAfter=<s> next to freezeOn means the moment only counts after s seconds of play.
#  - caption: `*word*` is the ONE gold-swash word; " / " starts the sub-line. Headline ≤ 30 characters (without the
#    asterisks) and ≤ 7 words. No "|". store-frame.swift REJECTS smash, squish, squash, splat, kill, slam, "Fold to"
#    and the competitor's name; store-set.sh flags flat, "shut" on its own, quick, fast, free, prices and "#1" (in the
#    sub-line too: "Fast close" on the CHOMP card is the app's own text, inside the capture, never in a caption).
#  - frame: flat (default) or book:<Duo scenario> = the book-pose composite of that Duo capture (store-frame --book);
#    P01's own capture here is only the fallback if the Duo capture is missing (then P01 is FLAGGED: never upload a
#    flat P01 without telling the founder).
#  - No fold here: every iPhone frame must log an unfolded canvas with the HUD on the right
#    ("SNAP-T canvas WxH fold=0 hudLeft=0", required by the workflow). These phones have no hinge: a tap is the bite,
#    and the hints say "Tap to snap". A pilot plays every play frame.
#
# R9 (design/notes/store-R9.md), the R8 game: the phone IS the trap (open phone = open trap; the bite fires as the
# phone closes, at about 18° or the closed status; a partial close never bites; every hinge round starts closed);
# on other iPhones a tap bites. 30 Levels in 3 worlds (Morning Bog 1–10, Dusk 11–20, Night 21–30, 1–3 stars, the next
# world at 20 stars) replace the First Bite lesson; Endless (the old Feed), the Daily Bog and the Zen Bog remain.
#  - The iPhone set never shows the Duo's outer-display CHOMP card (a Duo-only screen; it is D02 in the Duo set).
#  - ONE progress state, `late`, on every frame that shows progress (P04 map ★ 60 of 90, P06 Garden 6/8, P07 Book
#    16/16, P09 Home ★ 60 · 6/8 · 16/16, P10 Results), so the set reads as one player. build-metadata.js checks it.
#  - Every play frame's args are the ones proven in R8 CI (artifacts/r8, ci/scenarios.txt): bigFeast (48: 5 bugs
#    +360, "FEAST! +2 snaps", the lobes open again), bee wave 15 (12), night wave 24 landed (35: froze; wave 26
#    crowd did NOT freeze in R8), the levels map late (60), Home late (52), Results expert (50: goals ticked).
#  - No level-results frame: in R8 CI the perfect pilot did not pass Level 1 (`SNAP-T level result 1 stars=0`; app
#    ask in store-R9.md). A frame that needs a level won is unsafe until that is fixed.
# Truthfulness (screenshots.md checklist): a Feast is ≥ 3 bugs (+1 snap); a FEAST is a clean bite of ≥ 5 (score ×2,

# → dusk (wave 15) → night (wave 23); 16 Bug Book species; 8 Garden flytraps; 3 goals at a time from 39; 30 levels,
# 3 stars each (90). If any of these change, change the caption.
